# Мануал - Ticket Manager: Как Понять и Оптимизировать Код

---

## 1. Архитектура (как всё устроено)

```
Пользователь (браузер http://localhost:5173)
      │
      ├-- REST API запросы --► Express (порт 3847) --► SQLite (data/tickets.db)
      │                                │
      └-- WebSocket (ws://...3847/ws) ◄-┤--► Ubisoft API (через прокси)
                                        ├--► 2Captcha API
                                        ├--► OpenRouter / DeepSeek API (AI)
                                        └--► CamoFox (child_process)
```

**Vite** (порт 5173) - девелоперский сервер для фронтенда. Проксирует `/api/*` и `/ws` на Express.
**Express** (порт 3847) - бэкенд. Все API-роуты, WebSocket, фоновые циклы.
**SQLite** - файловая БД в `data/tickets.db`, WAL-режим = запись мгновенная и крашбезопасная.

---

## 2. Запуск

```bash
cd ticket-manager
npm install          # первый раз
npm run dev          # запускает и фронт и бэк
```

Это запускает `concurrently`:
- `node --watch server/index.js` - бэкенд с авторестартом
- `vite` - фронтенд с HMR

### `server/database.js` - База Данных

**Что делает:** Схема таблиц, все CRUD-операции.

| Таблица | Что хранит |
|---------|-----------|
| `accounts` | Ubisoft-аккаунты (логины, токены, статус, заметки) |
| `tickets` | Тикеты поддержки (номер кейса, статус, платформа, даты) |
| `messages` | Сообщения в тикетах (текст, кто отправил, время) |
| `failed_accounts` | CSV-строки, которые не удалось обработать |
| `settings` | Ключ-значение (прокси, API-ключи, интервалы) |

**Ключевые моменты:**
- WAL-режим (`pragma journal_mode = WAL`) - каждый INSERT/UPDATE сразу на диск
- `better-sqlite3` - **синхронная** библиотека, т.е. запись не бывает "отложенной"
- `ON DELETE CASCADE` - удалил аккаунт -> его тикеты и сообщения удаляются автоматически
- Индексы на `status`, `platform`, `opened_at`, `week_number` - для быстрой фильтрации

**Как модифицировать:**
- Новое поле -> добавь в `CREATE TABLE` (строки 31-111) + обнови INSERT/UPDATE/SELECT
- Новый запрос -> добавь `export function myQuery()` по образцу существующих

### `server/ubisoft-api.js` - Ubisoft API Клиент

**Что делает:** Все HTTP-запросы к Ubisoft.

| Функция | Что делает |
|---------|-----------|
| `authenticate(email, pass, proxy)` | Логин через Basic Auth -> `/v3/profiles/sessions` (3 попытки) |
| `refreshToken(ticketData, proxy)` | Обновляет токен через существующий -> тот же endpoint |
| `createTicket({...})` | Создаёт тикет восстановления -> `account-recovery-cases` |
| `closeTicket(caseNumber, opts)` | Закрывает тикет -> `PUT /case/{id}` с `status: 2` |
| `sendComment(caseNumber, body, opts)` | Отправляет ответ -> `POST /case/{id}/comment` |
| `getTicketStatus(caseNumber, opts)` | Получает статус тикета |
| `getTicketInteractions(caseNumber, opts)` | Получает историю переписки |
| `makeRequest(endpoint, opts)` | Базовая функция для всех запросов (прокси, хедеры, логи) |

**Прокси:** Используется через `https-proxy-agent` + `node-fetch`. Формат: `user:pass@host:port`.

**Как модифицировать:**
- Новый API-эндпоинт -> добавь функцию, которая вызывает `makeRequest()` с нужным путём
- Изменить хедеры -> редактируй `BASE_HEADERS` (строки 8-19) или `getAuthHeaders()`

---

### `server/token-manager.js` - Автообновление Токенов

**Что делает:** Фоновый цикл, обновляет токены за 15 минут до истечения.

- Запускается при старте сервера (`startTokenManager()`)
- Интервал по умолчанию: 50 минут (настраивается)
- Первый запуск: через 10 секунд после старта
- Обновляет аккаунты **последовательно** (2 сек пауза между ними - защита от рейт-лимита)
- Если токен невалидный -> `manual_login_required` + уведомление
- `try-finally` гарантирует что `isRefreshing` всегда сбрасывается (не блокирует цикл навсегда)

---

### `server/ticket-monitor.js` - Мониторинг Тикетов

**Что делает:** Фоновый цикл, опрашивает Ubisoft API на предмет изменений.

- Интервал: 45 секунд (настраивается)
- Для каждого активного тикета:
  1. Проверяет статус (`getTicketStatus`) -> если изменился, обновляет в БД
  2. Проверяет сообщения (`getTicketInteractions`) -> если есть новые, сохраняет в БД
- Если ответил агент -> WS уведомление `new_agent_message` -> тост + звук + push
- Маппинг статусов Ubisoft -> наши: `Waiting->Awaiting Reply`, `Updated->Awaiting Response`, `Closed->Completed`

---

### `server/ticket-creator.js` - Создание/Управление Тикетами

**Что делает:** Полный жизненный цикл тикета.

| Функция | Шаги |
|---------|------|
| `createTicketForAccount()` | 1) Решить капчу -> 2) Создать через API -> 3) Сохранить в БД |
| `closeTicketById()` | 1) Закрыть через API -> 2) Пометить как Completed |
| `regenerateTicket()` | 1) Закрыть текущий -> 2) Подождать 2 сек -> 3) Создать новый |
| `replyToTicket()` | 1) Отправить через API -> 2) Сохранить в БД -> 3) Статус -> Awaiting Response |

---

### `server/captcha-solver.js` - Решение reCAPTCHA

**Что делает:** 2Captcha API для reCAPTCHA v3 Enterprise.

1. Отправляет задачу на `2captcha.com/in.php` (сайт-ключ, URL страницы, версия, enterprise)
2. Поллит результат на `2captcha.com/res.php` каждые 5 секунд
3. Таймаут - 120 секунд
4. Возвращает `{ success: true, token: '...' }` или ошибку

---

### `server/csv-parser.js` - Парсинг CSV

**Что делает:** Разбирает CSV на объекты аккаунтов.

- Автоопределение формата по полю `Platform Linked` (XBL/PSN в каждой строке)
- Разделяет `email:password` в Login Details и Platform Login
- Пароли с `:` - поддерживаются (join остатка после split)
- Ошибки парсинга -> попадают в `failed_accounts`

---

### `server/ai-assistant.js` - AI Подсказки

**Что делает:** Запрашивает у AI предложенный ответ на сообщение агента.

- Системный промпт: "ты владелец аккаунта, потерял доступ к платформе, хочешь отвязать"
- Контекст: платформа, юзернейм, контактный email
- История чата передаётся полностью
- Температура 0.8, макс 200 токенов

---

### `server/camofox-launcher.js` - CamoFox Браузер

**Что делает:** Запускает CamoFox через `child_process.exec()`.

- PSN: `camofox --proxy http://... --url "https://my.account.sony.com/central/signin" --no-close`
- Xbox: то же, но URL = `https://login.live.com/`
- `detached: true` + `child.unref()` - браузер живёт отдельно от Node.js
- Трекинг активных браузеров по accountId (нельзя открыть два для одного аккаунта)

## 5. Потоки Данных (как всё связано)

### Импорт CSV -> Логин -> Тикет -> Чат

```
CSV файл
    ↓ parseCSV()
Массив аккаунтов
    ↓ insertAccount() в БД
    ↓ attemptLogin() × 3 попытки
    ├-- Успех -> authenticated -> кнопка "Create Ticket"
    └-- Провал -> manual_login_required -> кнопка "Manual Auth" / "Retry"

Create Ticket:
    solveCaptcha() -> createTicket() API -> insertTicket() БД -> broadcast WS

Мониторинг (каждые 45 сек):
    getTicketStatus() -> если статус изменился -> updateTicketStatus() + broadcast
    getTicketInteractions() -> если новые сообщения -> insertMessage() + broadcast

Чат:
    openTicketChat() -> загружает тикет + сообщения + аккаунт
    Ответ пользователя -> replyToTicket() API + БД + broadcast
    AI подсказка -> getSuggestedReply() -> показать -> Accept/Edit/Regenerate
```

### Токены (фоновый цикл)

```
Каждые 50 минут:
    getAuthenticatedAccounts()
    Для каждого: если до истечения < 15 мин -> refreshToken()
    ├-- Успех -> updateAccountAuth() новый токен
    └-- Провал (INVALID_TOKEN) -> manual_login_required + уведомление
```

## 6. Сравнение с ТЗ - Что НЕ Сделано / Неправильно

### ❌ AI-провайдер НЕ соответствует ТЗ

> ТЗ: "AI не может принадлежать западным странам. Оплата крипто. Хостинг в России или Китае."

**Текущее:** OpenRouter (openrouter.ai) - **американская** компания. Модель DeepSeek - китайская, но сервис-посредник американский.

**Варианты решения:**
1. **DeepSeek API напрямую** (api.deepseek.com) - китайская компания, серверы в Китае. Но крипто не принимают (Alipay/WeChat).
2. **Найти провайдера в РФ/Китае с оплатой крипто** - пока нет очевидного кандидата с OpenAI-совместимым API.
3. **Оставить OpenRouter** - технически модель китайская, но формально сервис US.

> [!WARNING]
> Нужно решить: или менять провайдера, или принять текущее решение как компромисс. Код менять просто - `ai-assistant.js` строки 6 и 68, только URL и хедеры авторизации.

### ⚠️ PSN автологин НЕ реализован

> ТЗ: "открывает camofox и **логинится** в PSN аккаунт"

**Текущее:** Открывает только страницу логина. Не вводит логин/пароль.

Для автологина нужна browser automation (Playwright/Puppeteer) внутри CamoFox или инъекция userscript'а через CLI-флаги CamoFox. Зависит от того, что поддерживает конкретная версия CamoFox.

### ⚠️ Заметки аккаунтов в UI

> ТЗ: "секция Notes под информацией для Xbox и PlayStation"

**Текущее:** Заметки есть для **тикетов** (в чат-сайдбаре), но НЕ для **аккаунтов** отдельно. В БД поле `accounts.notes` существует, API `PUT /api/accounts/:id/notes` работает, но в UI на странице Accounts нет текстового поля для редактирования заметок.

### ✅ Остальное соответствует ТЗ

Все остальные пункты ТЗ реализованы корректно:
- GUI ✅, SQLite WAL ✅, Удаление данных ✅, Статистика по неделям ✅
- Фильтры (платформа, статус, дата) ✅, Чат-интерфейс ✅
- Close/Regenerate ✅, CamoFox кнопки ✅, Уведомления ✅
- Токены + авторефреш ✅, CSV импорт + автологин (3 попытки) ✅
- Ручная авторизация JSON ✅, Failed accounts секция со счётчиком ✅
- Создание тикета + капча ✅, Закрытие/Ответ/Мониторинг ✅
- AI не авто-отправляет ✅, кнопка Regenerate для AI ✅

## 7. Как Оптимизировать

### Где искать bottleneck'и:

1. **CSV импорт с логинами** - сейчас последовательный (1 аккаунт за раз + 1.5с пауза). Для 100+ аккаунтов можно сделать параллельно пачками по 3-5 с контролем рейт-лимита.

2. **Ticket monitoring** - поллит ВСЕ активные тикеты каждые 45 сек. При 50+ тикетах это 100+ API-запросов за цикл. Можно приоритизировать: `Awaiting Reply` поллить чаще, `Awaiting Response` - реже.

3. **Фронтенд main.js 875 строк** - один файл. Для масштаба можно разбить на модули (dashboard.js, tickets.js, chat.js, etc.) и импортить через Vite.

4. **Canvas бар-чарт** - самописный. Для сложной статистики можно заменить на Chart.js (лёгкая библиотека).

### Что безопасно менять:

| Файл | Что можно менять | Осторожно |
|------|-----------------|-----------|
| `index.css` | Любые стили, цвета, анимации | Имена CSS-классов используются в main.js |
| `main.js` | Вёрстка страниц, новые кнопки | Не ломай `api()` и `broadcast` обработчики |
| `database.js` | Новые таблицы, новые поля | Не меняй существующие поля - сломает данные |
| `ubisoft-api.js` | Хедеры, новые эндпоинты | Не трогай `makeRequest()` без необходимости |
| `ai-assistant.js` | Промпт, модель, URL | Самый безопасный файл для экспериментов |
| `settings` | Все настройки через UI | Не хардкодь значения, бери через `getSetting()` |
