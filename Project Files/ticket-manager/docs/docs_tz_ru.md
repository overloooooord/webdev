# Техническое Задание - Ticket Manager (Ubisoft Account Recovery)

---

## Основные функции

### 1. Графический Интерфейс (GUI)

Программа должна иметь графический интерфейс - будь то Telegram-бот, Zendesk-подобная программа, Tkinter или веб-страница на HTML.

---

### 2. Локальная База Данных (SQLite)

- Данные тикетов сохраняются локально в файл SQL-базы данных. БД автоматически загружается при запуске Ticket Manager и обновляется при создании, изменении и прочих действиях с тикетами.
- **ОБЯЗАТЕЛЬНО**: база данных должна обновляться в реальном времени на случай краша хост-ОС или виртуальной машины, на которой запущен софт.
- Должно быть меню/функционал для **удаления данных тикетов** - иногда нужно тестировать Ticket Manager или исправлять ошибки в тикетах.

---

### 3. Лог выполненных тикетов по неделям

- Вести лог завершённых тикетов за каждую неделю (неделя начинается с воскресенья).
- Должна быть **визуальная диаграмма** (например, столбчатая), с возможностью фильтрации по конкретному месяцу.

---

### 4. Фильтрация тикетов

- **По типу тикета**: Xbox или PlayStation. Это важно, потому что каждый тикет использует одну из двух платформ.
- **По статусу тикета**:
  - `Open` - открыт
  - `Awaiting Reply` - ожидает ответа от пользователя (нужно написать в тикет)
  - `Awaiting Response` - ожидает ответа от агента Ubisoft Support
  - `Completed` - завершён
- **По дате открытия** (например: показать только тикеты, открытые 13.07.2026 со статусом "Awaiting Reply")

---

### 5. Чат-интерфейс тикетов

Каждый тикет должен быть разделён в отдельный чат-интерфейс:

- **Ответы агента Ubisoft Support** обновляют тикет в GUI.
- **Ответы пользователя** через Ticket Manager также отправляют API-запрос для обновления тикета на стороне Ubisoft.
- Где-то должна отображаться **релевантная информация о тикете** - она подтягивается автоматически из данных, введённых в Ticket Manager (описано ниже).
  - Для привязанных аккаунтов Xbox и PlayStation должна быть секция **"Заметки"** под информацией - для любых заметок, связанных с тикетом (например, новый email аккаунта после завершения тикета).

- **Управление тикетом** - должны быть кнопки:
  - **"Close Ticket"** - закрывает текущий тикет и НЕ создаёт новый.
  - **"Regenerate Ticket"** - закрывает текущий тикет И создаёт новый.
  - Эти кнопки нужны, потому что иногда тикет заходит в тупик: агент не отвечает или начинает подозревать и эскалирует тикет.

- **Для аккаунтов с привязкой PlayStation**: должна быть кнопка в GUI, которая открывает **CamoFox-браузер** и логинится в привязанный PlayStation-аккаунт. Браузер остаётся открытым, пока пользователь вручную его не закроет.
  - Это нужно, потому что для верификации в тикете используется PlayStation или Xbox аккаунт. Проблема с PlayStation в том, что у них более агрессивные рейт-лимиты, и мы не можем нативно залогиниться в аккаунт для верификации без CamoFox-браузера с прокси.
  - **(ОПЦИОНАЛЬНО)** Для аккаунтов с привязкой Xbox - аналогичная кнопка, открывающая CamoFox-браузер с прокси, но БЕЗ автоматического логина. Браузер также остаётся открытым до ручного закрытия.

---

### 6. Система уведомлений

- Уведомляет пользователя **в реальном времени** о новых ответах от агентов Ubisoft Support.

---

### 7. Генерация токенов Ubisoft-аккаунтов + автообновление

- Токены Ubisoft (Ubisoft называет их "tickets", но для избежания путаницы здесь - "токены") **истекают каждый 1 час**.
- Токены должны автоматически обновляться (используя текущий токен для создания нового с новым таймером на 1 час).

---

### 8. Автоматическое создание тикетов

#### 8.1. Импорт данных из CSV

Ticket Manager должен автоматически подтягивать данные из `.csv` файлов с логинами Ubisoft-аккаунтов и данными для верификации тикетов на восстановление аккаунта.

**Формат CSV для Xbox:**
```
Username,Account Level,Login Details,Platform Linked,Platform Login,Backup Email,Date Linked
```

**Формат CSV для PlayStation:**
```
Username,Account Level,Login Details,Platform Linked,Platform Login,Platform Email,Platform DOB,Date Linked
```

- В обоих форматах **"Login Details"** - это логин/пароль от Ubisoft-аккаунта, а **"Platform Login"** - логин/пароль от Xbox/PlayStation.
- Иногда CSV-файлы содержат **смешанные** аккаунты (и Xbox, и PlayStation). Для упрощения поле **"Platform Linked"** показывает `XBL` для Xbox и `PSN` для PlayStation.

#### 8.2. Автоматический вход в аккаунт

После подтягивания данных из CSV, программа должна сначала попытаться залогиниться в аккаунт через **Login Details**. Если логин не удался - аккаунт отображается в секции тикетов со статусом **"Manual Login Required"**.

- Логину даётся до **3 попыток** - бывают проблемы с логином через API и вебстраницу.
- Для аккаунтов со статусом "Manual Login Required" должна быть возможность вручную ввести **JSON-словарь с данными авторизации** (пример ниже). Токен Ubisoft берётся из `json_dict['ticket']`.

**Пример JSON авторизации:**
```json
{
  "platformType": "uplay",
  "ticket": "ewogICJ2ZXIiOiAiMSIs...<длинный токен>",
  "twoFactorAuthenticationTicket": null,
  "profileId": "Aq0Ykxyh-0191-0b33-1111-NdB8aicxKzGL",
  "userId": "Aq0Ykxyh-0191-0b33-1111-NdB8aicxKzGL",
  "nameOnPlatform": "EXAMPLE_USER",
  "environment": "Prod",
  "expiration": "2026-07-13T17:10:22.67134071",
  "spaceId": "8f9fe635-253f-4550-9205-bc797b22ae38",
  "clientIp": "000.00.00.000",
  "clientIpCountry": "RU",
  "serverTime": "2026-07-13T17:10:22.67134071",
  "sessionId": "82b8e10b-cac4-41c6-96bd-dc73eedb5431",
  "sessionKey": "BlI1UIpMAoq...",
  "rememberMeTicket": "ewogICJ0eXAiOiAi..."
}
```

- Если **оба метода** входа (автоматический + ручной) не сработали - строки из CSV попадают в **отдельную секцию** программы, с отображением общего количества таких строк.

#### 8.3. Обновление токенов без повторного логина

Токены Ubisoft истекают каждый час. Обновление происходит через функцию `refresh_token` класса `Ubisoft_API` - она принимает текущие данные авторизации и возвращает аналогичные, но с новым токеном. Это позволяет избежать повторного логина через Login Details или Platform Login, что может пометить аккаунт как подозрительный.

#### 8.4. Создание и мониторинг тикета

После успешного логина аккаунт создаёт тикет и мониторит его на предмет ответов.

### 9. API-запросы (подробности)

#### 9.1. Создание тикета

- **Endpoint:** `POST https://public-ubiservices.ubi.com/v1/applications/global/cshelp/cases/api/account-recovery-cases`
- **Ответ:**
```json
{
  "item": "500Rm00001UybmAIAR|26358701",
  "errorMessage": null,
  "statusCode": null
}
```
- Переменная `item` содержит номер кейса. В примере `26358701` - это номер кейса, который нужно извлечь, убрав первую половину строки.
- **ВАЖНО:** Создание тикета через Ubisoft требует **reCAPTCHA-токен**, который передаётся в JSON под переменной `token`. Для генерации валидных токенов используется сервис **2Captcha** (он же RuCaptcha). Предположительно используется **reCAPTCHA v3 Enterprise**.
  - API-ключ 2Captcha / RuCaptcha: `3929d3ab5b72747c0ffb4caccf17bddf`
- Переменная `emailAddress` в JSON - это контактный email для верификации. Туда отправляется верификационное письмо. В качестве контактного email используется **email от платформенного логина** (Platform Login).

#### 9.2. Закрытие тикета

- **Endpoint:** `PUT https://public-ubiservices.ubi.com/v1/profiles/me/global/cshelp/cases/api/case/{caseNumber}`
- Число в URL - номер кейса (для каждого аккаунта разный). В JSON-данных статус `2` - это закрытие тикета.

#### 9.3. Отправка ответа в тикет

- **Endpoint:** `POST https://public-ubiservices.ubi.com/v1/profiles/me/global/cshelp/cases/api/case/{caseNumber}/comment`
- Число в URL - номер кейса. В JSON-данных передаётся текст ответа.

#### 9.4. Получение информации об открытом тикете

Два endpoint'а:

**Статус тикета:**
- **Endpoint:** `GET https://public-ubiservices.ubi.com/v1/profiles/me/global/cshelp/cases/api/case/{caseNumber}`
- Статус находится в `json_dict["status"]["name"]`
- Примеры статусов:
  - `"Updated"` - ожидание ответа агента Ubisoft Support
  - `"Waiting"` - ожидание ответа пользователя (то есть нас)
  - `"Closed"` - тикет закрыт
  - Есть и другие (например, для только что созданного тикета, на который агент ещё не ответил), но они менее важны - достаточно ждать статус `"Waiting"` и тогда уведомлять пользователя о новом ответе.

**Лог переписки:**
- **Endpoint:** `GET https://public-ubiservices.ubi.com/v1/profiles/me/global/cshelp/cases/api/case/{caseNumber}/interactions/?offset=0&limit=9999`
- Ответ содержит переписку в `response["interactions"]`, отсортированную от самого нового к самому старому (т.е. `response["interactions"][-1]` - это первое сообщение).
- Каждый элемент содержит:
  - `"createdBy"` - кто отправил сообщение (`"Technical API"` = пользователь, `"Ubisoft Agent"` = агент поддержки)
  - `"createdAt"` - время отправки (например: `2026-07-14T09:00:47`)

### 10. Интеграция ИИ (Важная функция)

В чат-интерфейсах тикетов должна быть **интеграция с ИИ**. Требования:

- ИИ **НЕ может** принадлежать западным странам (США, страны ЕС).
- Сервис должен принимать оплату в **криптовалюте**.
- Хостинг должен быть в **России или Китае**.
- ИИ автоматически **читает ответы агентов** Ubisoft Support и **предлагает** подходящий ответ.

**Важно:**
- Предложенный ответ **НЕ ДОЛЖЕН** отправляться автоматически без одобрения пользователя.
- Должна быть кнопка **"Regenerate"** для генерации другого варианта ответа от ИИ.
